# טפסי רישום לאירועים

## שימוש

באירועים של מנהל או רכז: לחצו **טופס רישום** בכרטיס האירוע, או **נרשמים וספקים → טופס רישום**.

אפשר לערוך את כותרת הטופס והפתיח, להעלות לוגו PNG/JPG/WebP עד 200KB, להוסיף עד 20 שדות, לשנות סדר, להגדיר שדה חובה ולבחור סוג: טקסט קצר/ארוך, טלפון, אימייל, מספר, רשימת אפשרויות, תיבת סימון או תעודת זהות. כפתור **שכפול** מעתיק שדה מיד לאחר המקור עם מזהה חדש, ושומר את הסוג, החובה וכל אפשרויות הרשימה. אפשר לערוך את העותק באופן עצמאי. שם וטלפון נשארים חובה לזיהוי ולמניעת רישום חוזר. תעודת זהות נבדקת בספרת ביקורת אם מוסיפים שדה מהסוג הזה.

הטופס הציבורי משתמש באותה שפה חזותית של טופס הלידים: טורקיז כהה וזהב, פרטי אירוע בצד, שדות לבנים מעוגלים, ועמודה אחת בטלפון. התצוגה המקדימה והעמוד הציבורי חולקים את הרכיב `EventRegistrationSurface`.

הפעילו **פתיחת ההרשמה**, שמרו ואז העתיקו את הקישור. הכתובת היא `/register/<event-slug>`. השם והלוגו משנים את טופס האירוע בלבד. טופס הלידים הישן `/j/event/<slug>` ממשיך לפעול ואינו מוסב אוטומטית לרישום.

בטאב **נרשמים** מופיעים גם הנרשמים מהקישור, מועד ההרשמה ותשובות השדות תחת **פרטי ההרשמה**. סימון הגעה, קידום מהמתנה, הוספה ידנית וניהול הספקים נשמרו. לכל הרשמה נשמר צילום של כותרות השדות, כך שעריכת הטופס בעתיד אינה מוחקת את משמעות התשובות הקודמות.

כשמכסת המקומות מלאה, ההרשמה מתווספת להמתנה. הרשמה חוזרת עם אותו טלפון באירוע אינה יוצרת משתתף נוסף. נעילת שורת האירוע מונעת משתי בקשות הרשמה לתפוס את המקום האחרון; גם ההוספה הידנית משתמשת באותו מנגנון אחרי המיגרציה. קידום ידני מהמתנה נשאר החלטת הצוות, כפי שהיה קודם.

## נתונים והרשאות

- המיגרציה: `supabase/migration-event-registration.sql`. היא מוסיפה טבלת הגדרות, שלוש עמודות תשובות ומפתח בקשה לנרשמים, אינדקסים ופונקציית רישום אטומית. אין מחיקה של אירועים, נרשמים, לידים או ספקים.
- קישור הרישום הציבורי מחזיר רק פרטי אירוע המוצגים בטופס והגדרות טופס פתוח. הוא אינו מחזיר רשימת משתתפים, טלפונים, תקציב או שיוך פנימי.
- כל שדה חובה, סוג ערך, אפשרות בחירה וגרסת טופס נבדקים שוב בשרת. תשובות לשדות לא מוכרים נדחות. שינוי טופס אחרי פתיחתו דורש מהנרשם לרענן לפני שליחה.
- הרשאות ניהול ושמירה נבדקות מול הרשאות האירועים ובעלות הרכז. בעלי הרשאת צפייה בלבד אינם יכולים לשמור. פעולות עדכון ומחיקת נרשם מוגבלות כעת גם למזהה האירוע שבנתיב.
- אין יצירת ליד אוטומטית, שליחת הודעת WhatsApp או דיוור מהטופס. זו הרשמה לאירוע; מנגנוני הלידים והדיוור נשארו נפרדים.

## אימות שבוצע

132 בדיקות עברו, מהן 40 חדשות לשדות, שכפול עצמאי של רשימות, סוגי נתונים, שדות חובה, תעודת זהות, הרשאות, כשל לפני מיגרציה, גרסאות מתנגשות ונתונים ציבוריים מינימליים. TypeScript נבדק בנפרד.

בענף Neon מבודד `br-solitary-sea-ax6p0c72` נבדקו החלת מיגרציה פעמיים, רישום, מניעת כפילות עם טלפון בפורמט שונה, מילוי קיבולת, הוספה ידנית לרשימת המתנה ושתי הרשמות מקבילות למקום אחד. נבדקה דחייה בשרת של טופס סגור ושל גרסה מיושנת. כל רשומות הבדיקה נוצרו בענף המבודד בלבד.

מגבלות: בניית Next המלאה ושרת הבדיקה המקומי נחסמים בסביבת Codex בהרשאות Windows לאימות נתיב הפרויקט. לא הושלמה בדיקת ממשק בדפדפן או רישום אמיתי באתר החי. קובץ התצוגה המצורף משתמש ברכיבי המערכת עם API מלאכותי בזיכרון בלבד; הוא אינו בדיקת חיבור למסד. יש להריץ בנייה ולבדוק מחשב וטלפון לפני פרסום.

מצב מיגרציית הייצור מתועד ב־`EVENT-REGISTRATION-VERIFICATION.json` אם הקובץ קיים. קוד הריצה אינו מחיל DDL אוטומטית. בהיעדר המיגרציה מוצגת הודעה בבונה הטופס, וההוספה הידנית הישנה ממשיכה לעבוד.

## פרסום מהטרמינל

לאחר שהמיגרציה הוחלה במסד המיועד ולאחר בדיקת התצוגה, אפשר להריץ מכל PowerShell:

```powershell
& {
    Set-Location -LiteralPath 'C:\Users\ElazarMiara\Desktop\עבודה נתיבים\מערכת נתיבים\netivim-hub'
    npm run build
    if ($LASTEXITCODE -ne 0) { throw 'הבנייה נכשלה; לא בוצעה דחיפה' }
    git add -- @(Get-Content -LiteralPath '.\docs\EVENT-REGISTRATION-FILES.txt')
    if ($LASTEXITCODE -ne 0) { throw 'הוספת הקבצים נכשלה' }
    git commit -m "Add configurable event registration forms"
    if ($LASTEXITCODE -ne 0) { throw 'יצירת הקומיט נכשלה' }
    git push origin HEAD:main
    if ($LASTEXITCODE -ne 0) { throw 'הדחיפה נכשלה' }
}
```

יש לבדוק שענף main הוא ענף הפרסום של האתר ב־Netlify. סביבת בדיקה של האתר צריכה להשתמש במסד בדיקה נפרד. במקרה של רגרסיה, אפשר להחזיר את קומיט הקוד עם `git revert`; העמודות שנוספו תואמות לקוד הישן ואינן דורשות מחיקה לצורך חזרה.
